# Upgrade to 0.3.0-preview.46

This preview adds the local SSH takeover transaction and independent recovery executor. The management takeover API remains disabled until Controller orchestration and independent login verification are connected. The Web workspace still needs its real API implementation; no production host has been switched by this development work.

## Local transaction and recovery

- Persist root-only backups, file permissions, checksums, boot identity, the immutable five-minute deadline and legacy connection identities before changing authentication. Reject preflight drift, concurrent unresolved journals and idempotent requests that change their baseline.
- Arm and confirm a separate systemd timer before applying the flat SSH/PAM configuration. The timer uses a suspend-aware boot clock and a standalone root service, independent of the Controller, Agent and running helper.
- Keep unfinished application journals recoverable rather than replaying an uncertain change. Include old-auth handshakes admitted between initial preflight and reload in the legacy connection set.
- Commit accepts a reference to independently collected Controller evidence; collecting and authorizing that evidence is still pending. It checks the current configuration, closes legacy processes by validated process identities and persists the committed state before cancelling rollback. A late timer cannot reopen old authentication after commit.
- Restore backed-up files atomically, preserve their exact modes/group, validate syntax and the active listener, and distinguish successful restoration from manual-recovery-required. Before ssh.service/socket startup after a reboot, recover any unfinished trial; public readiness must still be based on fresh listener evidence.
- Serialize helper transactions and independent recovery under the same kernel flock. Recovery accepts only a plan UUID or the fixed boot action; it has no Controller/network credential dependency and accepts no caller-selected shell, executable or configuration path.

## Validation

Disposable Debian 12 and Ubuntu 24.04 native systemd VMs each passed all 42 helper/native tests. Actual authentication switches on both distributions rejected a previously valid root public key, preserved the old control connection until it was closed, and restored exact baseline configuration and fresh key login after the full five-minute deadline without a running helper or Controller. Separate reboot drills restored deliberately invalid trial configuration before SSH startup and confirmed the recovery service succeeded.

These exercises exposed and fixed entrypoint detection through the installed `current` symlink and restored-file permissions under the service's strict umask; both have dedicated regressions. Windows passed 29 applicable helper tests (nine Linux tests skipped), helper type checking, targeted lint and two release workflow tests. This evidence does not yet certify OTP-based SSH login, independent Controller verification, SFTP/SCP, authorization revocation or the Web workflow. Hosted CI remains pending while GitHub's workflow OAuth permission is unavailable.

All workspace packages, internal dependencies, the lockfile and current version documentation advance together. Schema remains 12; Agent protocols remain 1.0/1.1. Recovery units are passive release files until an explicit supported helper installation; a software upgrade does not switch SSH authentication.
