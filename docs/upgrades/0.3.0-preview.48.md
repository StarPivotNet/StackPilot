# Upgrade to 0.3.0-preview.48

This preview adds passive installation and explicit helper enrollment. Software installation leaves `/etc/ssh/sshd_config`, `/etc/pam.d/sshd` and service activation unchanged. Takeover remains an independently requested, verified operation. The Web integration, drift repair workflow and full fault/profile acceptance matrix are still pending.

Database schema remains 12. Controller and Web versions must match; back up persistent state before upgrades. There is no automatic down migration. See [SSH installation](../ssh-access.md#native-helper-installation).

Use only native Debian 12 or Ubuntu 24.04 x86_64 with systemd/cgroup v2. Installation requires root, Node 22, npm, a C compiler, PAM development headers, sudo and stock OpenSSH. Native binaries are compiled on the target so their libc ABI matches that host. Release source must be verified, root-owned and not writable by other users.

Stop the helper explicitly before installing or upgrading. Existing SSH scopes retain their deadlines; new managed logins remain unavailable while the helper is stopped. An unfinished takeover must be resolved first. Install with `node deploy/scripts/install-ssh-helper.mjs install`, configure protected files and explicitly enroll/start the service. Installation never reenrolls a helper or reopens legacy authentication.

Explicit reenrollment generates a new Ed25519 key and stores the key/credential binding atomically. It revokes previous host identity and invalidates independent verification. It is a deliberate identity operation, not an upgrade step. A lost enrollment response requires a new one-use token.

Installer, protected-store and boot-dependency tests were exercised on disposable supported VMs; production deployment and complete release/security gates remain outstanding.
